# 调试与常见问题

## 推荐顺序

先无绳检查机构和碰撞 → 只加一条绳 → 小预紧 → 小收绳 → 检查张力/状态 → 再增加摩擦和复杂控制。一次只改变一个可解释的因素，保存 XML 版本。

## 症状对照

| 症状 | 优先检查 | 最小处理 |
|---|---|---|
| 不认识 `plugin:control_timeconstant` 等属性 | 实际加载的库不是新编译库 | 重编译；退出所有旧 viewer；检查 `--plugin` 指向 |
| `wrap_geoms count...role-2` | hint 与 geom 数量/次序 | 展开 seed，逐个计数；不要把 guide 误标成 hint |
| 绳是经过球体的直线 | 看见的是原生 seed | seed 设近零合法宽度；确认 surface 实例和 runtime 绘制 |
| 空中出现折角/支撑长杆 | guide 的几何与物理含义 | role-3 只能放真实导向；虚构支点会改变力臂 |
| 端点似乎没连在刚体上 | site 父 body 和坐标变换 | 可视化局部坐标；检查毫米/米和 mesh 变换 |
| 绳从端面/侧面走 | 初始化走廊、厚度方向 | 把端点/hint 放到合适截面；重新初始化 |
| 绳穿过别的物体 | 障碍没列入 wrap 配置 | 明确配置相关表面；不是全场景自动绳碰撞 |
| 绳长为 0，路径留在原地 | route invalid 或旧显示 | 检查状态 8；invalid 样本不能当正常绳长 |
| 收绳却不动 | 余量、受力、约束、控制源 | 先看 T，再看 c/Lf；检查 hinge、equality、范围和自动控制覆盖 |
| 整个关节锁死 | 过紧多索、接触初始穿透、过大 k | 降预紧/刚度，只留一对韧带验证剩余自由度 |
| 表面抖动/张力跳变 | 控制跳变、接触面粗糙、路线换集 | 降速率、查残差与接触；再试迟滞/平滑 |
| 拖滑块很卡 | 单步耗时与 GUI 同步节奏 | 分开测 step/copy/render；不要用放大物理步长掩盖 |
| 滑轮落地后绳仍包着 | 对侧仍拉紧或固定分支 | 松弛 T=0 不等于已模拟真实下垂和自动脱离 |

## 需要看哪些显示

```bash
./scripts/run_demo.sh 25 --show-route-debug --show-cable-state --duration 120
```

调试显示可能同时显示 seed 顺序、hint 和包络面。它们用于排查，不是都在施加力。正式展示时关闭调试层，再检查真实路线是否贴合。

site 球的大小、seed 宽度与 `visual_width` 是不同层级。surface 的 `visual_width` 是 scene 线宽显示参数，不是以米计的绳半径，也不会给绳增加碰撞厚度。

## 一个有意义的诊断日志

至少记录 `time, ctrl, contraction, L, Lf, T, route_status, tangent_residual, surface_residual`，再记录相关 body 位姿、速度、接触数和关节限位。对 invalid 比例单独统计，不应把归零后的 T 混入平均后声称机构“摩擦很小”。

检查驱动来源时：surface 主要看 `qfrc_passive` 与 sensor；native 看 actuator transmission 与修正；理想基线还要检查 equality。直接赋值 qpos 的回放录像与真实绳驱录像应分别标记。

## 性能不等于稳定性

固定刚体局部路线缓存、可见性记忆和合力映射减少重复计算，但不证明任意运动都实时。复杂非凸 mesh 仍可能很慢。较小的 GUI 计算预算改善鼠标响应，不会凭空让物理时间变快。

不要仅通过改大 timestep 追求实时；先做步长收敛，再比较位姿、张力、能量与接触。路径显示平滑不能修正真实绳路、材料或碰撞建模错误。
